设计说明
  • 验证码优先：自建邮箱最高频用途就是收验证码，所以详情页把验证码做成高亮胶囊 + 一键复制，视觉权重仅次于主题。后端已有 AI 验证码识别（aiCode），前端可直接消费。
  • 克制用色：强调色只用于「可点击的主动作」与「需要注意的状态」——底栏当前项、FAB、主按钮（复制 / 回复 / 发送）、未读点、验证码胶囊、开关与用量条。其余全部中性灰阶，接近 Gmail / Material 3 的取向，不做渐变与装饰插画。
  • 列表信息密度：头像首字 + 主题 + 单行预览 + 时间，未读靠「加粗 + 蓝点」双重编码而非只靠颜色（照顾色觉障碍）。星标与附件用小图标挂在时间下方，不挤压主题行。
  • 底栏四项：邮件 / 已发送 / 星标 / 我的，与现有 Web 端路由一一对应（/inbox /send /star /setting），不新增后端接口即可跑通。
  • 所有触控目标 ≥ 48×48，图标按钮均带 aria-label；配色全部取自 design/tokens.css，未来接 Kotlin 时直接映射成 colors.xml。
  • 实现注记：① 列表需预留约 88dp 底部内边距，否则滚到底时末封邮件会被 FAB 永久压住；② 「既未读又加星」的组合态本稿未覆盖，实现时约定为「星标在上、蓝点在下」并排；③ 深色模式的 token 已在 tokens.css 备好但未做视觉验证。
  • 待你拍板：① 是否要深色模式（本稿只出了浅色）② 底栏第二项放「已发送」还是「草稿」③ 是否需要多账号快速切换（顶部下拉 or 侧边抽屉）。
